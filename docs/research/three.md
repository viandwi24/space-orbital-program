## Decisions that follow

- Log depth buffer on (ADR 0007), camera `near = 0.1 m`, `far = 1e13 m`. Floating origin keeps the float32 scene coordinates small near the vessel; the log depth buffer handles the depth range between a metre-scale vessel and a planet-scale body.
- Core Three objects (`Scene`, `Group`, `Mesh`, geometries, `PerspectiveCamera`) work without WebGL, so the scene model is unit-tested in Bun; only `WebGLRenderer` needs a browser (plan 009 `[manual]`).

## Plan 019: environment pipeline (checked 2026-10-16, three 0.186.1)

Facts below come from the pages named and, where a page was only an API stub, from the installed source under `node_modules/three/src` and `examples/jsm` (noted as "source").

| Topic | Fact | Source |
|---|---|---|
| `EffectComposer` | `new EffectComposer(renderer, renderTarget?)`; a passed target and its clone are the read/write buffers, so MSAA and `HalfFloatType` are chosen by the target we pass. `addPass`, `render(deltaTime)`, `setSize`, `setPixelRatio`. The last pass renders to the screen. | https://threejs.org/docs/pages/EffectComposer.html |
| `RenderPass` | `new RenderPass(scene, camera)` renders into the composer's buffer; works with the log depth buffer because the material shaders write `gl_FragDepth` themselves (source `ShaderChunk/logdepthbuf_fragment`). | source |
| `UnrealBloomPass` | `new UnrealBloomPass(resolution: Vector2, strength, radius, threshold)`; radius in `[0, 1]`; mip-chain blur; needs tone mapping enabled in the renderer. We use threshold 3 (HDR) so only the sun, lamps and plume bloom. | https://threejs.org/docs/pages/UnrealBloomPass.html |
| `OutputPass` | Last pass: applies `renderer.toneMapping`, `toneMappingExposure` and `outputColorSpace`; passes that need sRGB input (FXAA) must follow it. Render targets are not tone mapped, only the screen is; so custom shaders write linear HDR and include `<tonemapping_fragment>` + `<colorspace_fragment>`, which are no-ops inside the chain. | https://threejs.org/docs/pages/OutputPass.html · source `WebGLPrograms` (`toneMapping` is `NoToneMapping` for render targets) |
| `Sky` addon | Preetham "Practical Analytic Model for Daylight" skydome, scaled to enclose the camera; uniforms `turbidity`, `rayleigh`, `mieCoefficient`, `mieDirectionalG`, `sunPosition`. A ground-level dome: no planet curvature, no atmospheric rim from space. Not used; ADR 0027 uses a custom Rayleigh + Mie march. | https://threejs.org/docs/pages/Sky.html |
| Shadow map in r186 | Directional shadows use a native `DepthTexture` with `compareFunction = LessEqualCompare` and linear filtering (`PCFShadowMap`, hardware PCF: GLSL `sampler2DShadow`); `PCFSoftShadowMap` was removed. A custom shader can bind `light.shadow.map.depthTexture` and `light.shadow.matrix` as a `sampler2DShadow`. three's own "empty" shadow texture is never uploaded: binding it to a shadow sampler makes WebGL report `Mismatch between texture format and sampler type` and the draw is skipped, so a real depth texture with a compare function must always be bound (found in plan 019). | source `WebGLShadowMap.js`, `WebGLUniforms.js`, `WebGLTextures.js`; https://threejs.org/docs/pages/DirectionalLightShadow.html (stub) |
| Shadow camera | `light.shadow.camera` is an `OrthographicCamera`; set `left/right/top/bottom/near/far` then `updateProjectionMatrix()`; `mapSize`, `bias` (negative = lit more), `normalBias`, `radius`. | same page |
| `CSM` addon | `examples/jsm/csm/CSM.js` splits the camera frustum into cascades; our shadow is a box around the vessel and launch site, so a single fitted map is simpler. Not used. | source |
| `InstancedMesh` | `new InstancedMesh(geometry, material, count)`; `setMatrixAt`, then `instanceMatrix.needsUpdate = true`; call `computeBoundingSphere()` after setting spread-out instances or frustum culling uses a stale sphere. Used for trees, rocks and lamps. | https://threejs.org/docs/pages/InstancedMesh.html |
| `PMREMGenerator` | `fromScene(scene, sigma, near, far, { size, position })` returns the prefiltered cube as a render target; assign `.texture` to `scene.environment`. We render a procedural sky/ground scene and refresh it when the sun or altitude changed enough. | https://threejs.org/docs/pages/PMREMGenerator.html |
| Log depth and custom shaders | With `logarithmicDepthBuffer: true` every program gets `#define USE_LOGARITHMIC_DEPTH_BUFFER` and the renderer sets `logDepthBufFC = 2 / (log(far + 1) / LN2)`. A fullscreen shader writes `gl_FragDepth = log2(1 + viewDepth) * logDepthBufFC * 0.5` with `viewDepth` the distance along the camera forward axis (what `vFragDepth = 1 + gl_Position.w` carries for meshes). | source `ShaderChunk/logdepthbuf_*`, `WebGLRenderer.js` |
| Inverse projection with a 1e13 far plane | `projectionMatrixInverse` applied to NDC z = 1 divides by zero (w = 0) at this far plane; reconstruct view rays with NDC z = 0. | found in plan 019 |
| Hidden browser pane | `requestAnimationFrame` does not fire while the Browser pane is hidden; manual runs drive `update()` and `render()` from the console. | built-in browser skill; observed |

| `LatheGeometry` | `new LatheGeometry(points: Vector2[], segments = 12, phiStart = 0, phiLength = 2*PI)`; profile x must be > 0; rotates about Y. Source computes one normal per profile point averaged between neighbouring segments, so corners come out smooth. | `mergeGeometries` | `import { mergeGeometries } from 'three/addons/utils/BufferGeometryUtils.js'`; `(geometries, useGroups = false)`; with `useGroups` each input becomes a group (one material per input); all inputs need the same attribute set and indexedness, else `null`. We merge per material slot first, then merge the slots with groups, so a part is one `Mesh` with a material array. | https://threejs.org/docs/pages/module-BufferGeometryUtils.html · source `examples/jsm/utils/BufferGeometryUtils.js` |
| `MeshPhysicalMaterial` | Extra parameters over `MeshStandardMaterial`: `clearcoat` / `clearcoatRoughness` (0 default), `sheen*`, `iridescence*`, `transmission` (0). Costs more per pixel; effects are off unless set. `emissive` / `emissiveIntensity` come from the standard material and take HDR values (intensity > 1) which bloom above the chain threshold 3.0. | https://threejs.org/docs/pages/MeshPhysicalMaterial.html |

| `Points` / sprites | `Points` sizes are limited by the GL point-size range of the driver and cannot be rotated or shaped, so smoke and glow use instanced camera-facing quads (`InstancedBufferGeometry` with per-instance attributes) with a `ShaderMaterial`. Additive blending: `blending: AdditiveBlending, transparent: true, depthWrite: false`; the log depth chunks keep these sorting against the planet pass (depth test on, write off). | https://threejs.org/docs/pages/Points.html · source `ShaderChunk/logdepthbuf_*` |
| Custom materials in the chain | Plume, smoke and glow shaders output linear HDR and include `<tonemapping_fragment>`, `<colorspace_fragment>` and both log depth chunks, like the planet pass (plan 019). | plan 019 notes |

## Plan 027: terrain heights, haze, cloud layers, water (checked 2026-10-16, three 0.186.1)

| Topic | Fact | Source |
|---|---|---|
| `WebGLCubeRenderTarget` | `new WebGLCubeRenderTarget(size, options)`; the options are the render-target options (`format`, `type`, `minFilter`, `magFilter`, `generateMipmaps` default false, `depthBuffer`). Faces are 0 to 5 in the order +X, -X, +Y, -Y, +Z, -Z; `renderer.setRenderTarget(target, activeCubeFace)` selects the face to draw into. The terrain bake renders a fullscreen triangle per face with a `uFace` uniform and an orthographic dummy camera; the cube texture is bound to a `samplerCube` uniform (no flip, because a custom shader samples it directly). | https://threejs.org/docs/pages/WebGLCubeRenderTarget.html (2026-10-16) |
| Half-float colour buffers | With `EXT_color_buffer_float` enabled on a WebGL 2 context R16F, RG16F, RGBA16F (and the 32-bit float formats) are colour-renderable; RGB16F is not. Linear filtering of 16-bit float textures is core in WebGL 2. The bake uses RGBA16F (height in R, gradient in GBA); the post chain already needs the same extension. | https://developer.mozilla.org/en-US/docs/Web/API/EXT_color_buffer_float (2026-10-16; the Khronos registry page returned 403 to the fetch tool) |
| Heightfield ray marching | The height `y = f(x, z)` is traced by stepping along the ray until it falls below the surface, with a step that grows with the distance and shrinks near the ground, then a refinement of the last interval. Safe steps need a Lipschitz bound of the height function (relaxed sphere tracing); `terrain-model.ts` tests the step rule against a brute-force scan. Background on the safety of the step: Baboud and Eisemann, "Efficient and Accurate Terrain Rendering" (safety shapes per texel). | https://iquilezles.org/articles/terrainmarching (search excerpt only: the article itself returned 404 to the fetch tool, 2026-10-16) · https://graphics.tudelft.nl/~eisemann/publications/Baboud2011HeightField/article.pdf (search result) |
| Gerstner-style waves | A sum of sine components with `omega^2 = g k` (deep water) and phase speed `sqrt(g lambda / 2 pi)`; components shorter than about three pixels are faded out to avoid shimmer. The visual sea rounds `omega` to a whole number of cycles per 180 s so time can wrap. | standard linear wave theory; tested in `water-model.test.ts` |
| One hash, three values | `pcg3d` returns a `uvec3`; hashing a lattice corner once and using all three components makes a value-noise vector (a domain warp) cost one noise instead of three (`noiseF3`). | `shaders/atmosphere.glsl.ts` |
| Hidden pane and shader cache | In the hidden built-in browser pane a program compiled after the first frame, or the first compile of changed shader text, ran about 3x slower (pad scene 35 ms against 12 ms); loading the page a second time with the same shader text gave the fast program again. Frame times in journal 027 are from the second load. | observed, journal 027 |

## Plan 039: program precompile, timer query, render scale (checked 2026-10-17, three 0.186.x)

| Topic | Fact | Source |
|---|---|---|
| `WebGLRenderer.compileAsync(scene, camera, targetScene)` | Compiles the programs a scene needs without drawing, and resolves when they are linked; with `KHR_parallel_shader_compile` the driver compiles off the main thread (three polls the extension). The program cache is keyed by shader code and parameters, including **tone mapping and colour space, which depend on the current render target** (a target or the canvas), so a scene meant for the post chain is compiled with `setRenderTarget(target)` set. A material that is kept alive (not disposed) keeps its program in the cache. The first draw after it does not stall on the compiler, but a first switch still costs the CPU work around it (vegetation, biome maps, terrain bake: journal 039). | https://threejs.org/docs/pages/WebGLRenderer.html#compileAsync (2026-10-17) · source `WebGLPrograms.getProgramCacheKey` |
| `EXT_disjoint_timer_query_webgl2` | Exposed by Chrome/ANGLE on the M5 but read 77 ms for 24 ms frames in the hidden pane (journal 039), and it is missing on Safari and often disabled for privacy, so the quality governor uses the frame interval, not a GPU timer. | https://developer.mozilla.org/en-US/docs/Web/API/EXT_disjoint_timer_query_webgl2 (2026-10-17) · observed |
| Render scale | `setPixelRatio(r)` with `r` below the device ratio draws into a smaller drawing buffer that the browser scales up; no program or target recompiles except the post chain's targets, which `post.setSize` resizes. `Renderer.setRenderScale` multiplies the device pixel ratio this way. | https://threejs.org/docs/pages/WebGLRenderer.html#setPixelRatio |
| Hidden pane intervals | In a hidden built-in pane `requestAnimationFrame` runs in bursts and its interval read 8 to 10 ms for a 12.6 Mpx canvas and for a loop that blocked 47 ms per frame: frame intervals there say nothing about the GPU, so the governor cannot be run live in it. | observed, journal 039 |
