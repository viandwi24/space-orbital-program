## Decisions that follow

- Log depth buffer on (ADR 0007), camera `near = 0.1 m`, `far = 1e13 m`. Floating origin keeps the float32 scene coordinates small near the vessel; the log depth buffer handles the depth range between a metre-scale vessel and a planet-scale body.
- Core Three objects (`Scene`, `Group`, `Mesh`, geometries, `PerspectiveCamera`) work without WebGL, so the scene model is unit-tested in Bun; only `WebGLRenderer` needs a browser (plan 009 `[manual]`).

## Plan 050: half-resolution planet pass (checked 2026-10-17, three 0.186.1)

| Topic | Fact | Source |
|---|---|---|
| Nearest-depth and bilateral upsampling | A half-resolution pass is upsampled by reading the four low-resolution texels around a full-resolution pixel: nearest-depth takes the colour of the texel whose depth is closest to the pixel's own; the bilateral form starts from the bilinear weights and multiplies each by a similarity of its depth to the reference, which filters smooth surfaces and does not blend across edges. Practitioners warn that bilinear weights alone can pick a texel unlike the surface, and that nearest-depth leaves jagged edges when the low-resolution pass is not detailed enough: both are visible at 2 x 2 steps on cloud edges and ridges here. Here the full-resolution depth is not known before the pass, so the reference is the nearest low-resolution texel. | https://www.gamedev.net/forums/topic/657298-nearest-depth-upsampling/ · https://community.khronos.org/t/nearest-depth-upsampling/71981 · https://www.gamedev.net/topic/687338-ssao-halo-in-half-resolution/ |
| `WebGLRenderTarget` options | `depthBuffer: false` is valid (the march prepass uses it); `count` > 1 makes multiple render targets (`textures[]`) and needs `layout(location)` outputs, which three writes only as `pc_fragColor` for a `ShaderMaterial` unless `glslVersion: GLSL3`; `samples` is the MSAA count (the scene target keeps it, the half-resolution pass has none). Read from `node_modules/three/src/renderers/webgl/WebGLProgram.js` (`pc_fragColor`, `GLSL3`) and `WebGLRenderTarget.js`; the docs page (https://threejs.org/docs/pages/WebGLRenderTarget.html) lists the same options. | repo's three 0.186.1 |
| Log depth of the planet pass | `gl_FragDepth = log2(1 + z) * logDepthBufFC * 0.5` with `logDepthBufFC = 2 / log2(far + 1)`, so the fragment depth is `log2(1 + z) / log2(far + 1)`; a difference of two depths times `log2(far + 1)` is the octaves between the distances. Tone mapping applies only when drawing to the canvas (a render target gets none), so the upsample, not the half-resolution target, carries it on `low`. | `shaders/planet.glsl.ts`, `WebGLRenderer.js` (`toneMapping` for targets) |
| Hidden pane and programs, again | Changing a `defines` value at run time (`needsUpdate`) compiles a new program that runs 2 to 3 times slower in the hidden pane until a second page load finds it in the driver's cache: an A/B by toggling a define needs a warm-up load first (cloud shadows on `medium`: 25 against 13 ms on the first load). | observed, journal 050 |

## Plan 038: lakes, river flow, shore waves, site animation, precompile (checked 2026-10-17, three 0.186.1)

| Topic | Fact | Source |
|---|---|---|
| Flow maps with two phases | A flow map distorts a texture by sampling it at `uv - flow * progress`; `progress = frac(time + offset)` is a sawtooth, and two phases half a cycle apart (offset 0 and 0.5) are blended with the triangle weight `1 - abs(1 - 2 progress)`, which is 0 at a phase's own reset and makes the two weights sum to 1, so the reset is never visible. Adding noise to the time staggers the pulse; offsetting the second phase's texture lookup avoids a repetition. Used here with `flow` the river's tangent (`water-flow.ts`), the cycle 2.4 s (75 cycles in the sea's 180 s period). | https://catlikecoding.com/unity/tutorials/flow/texture-distortion/ |
| Shoaling and the breaker index | In the shallow-water limit the phase speed is `sqrt(g h)` (`omega / k`), so with a fixed frequency the wavenumber `k = omega / sqrt(g h)` grows and the wavelength shortens as the depth falls: the shore phase is `2 omega sqrt(x / (g slope)) + omega t` for depth `slope * x`. McCowan (1894) put the ratio of breaking wave height to depth at 0.78 for a solitary wave; Yamada et al. (1968) refined it to 0.8261; Goda (2010) argues it is not a constant, and a field study found 0.78 placed the breakpoint within about 5 m on a 300 m profile. Used as a first estimate for the surf band (`shore-wave.ts`). The Wikipedia page of wave shoaling gave the first facts, not the breaker index (searched separately). | https://en.wikipedia.org/wiki/Wave_shoaling · https://journals.flvc.org/jcr/article/view/77840 · https://www.ancientportsantiques.com/wp-content/uploads/Documents/ENGINEERING/Maritime/BW/WaveBreaking-Goda2010.pdf |
| Analytic noise derivatives | Value noise with a cubic or quintic fade has an analytic gradient from the same eight lattice values: `d/dx = (k1 + k4 v + k6 w + k7 v w) u'(x)` with `u' = 6x(1 - x)` (cubic) or `30 x^2 (x - 1)^2` (quintic); computing value and gradient together is about five times cheaper than central differences. Not adopted (draft 068): the terrain bake's height is a chain of ten functions (rotated octaves, a soft ridge, smooth maximum, smoothsteps), each needing its own derivative. | https://iquilezles.org/articles/morenoise/ |
| `compileAsync` and parallel compile | `WebGLRenderer.compileAsync(scene, camera, targetScene)` creates the programs in the call (synchronously) and resolves when `KHR_parallel_shader_compile` reports them ready, so starting all calls in one turn lets the driver compile side by side. Measured here: all 12 programs of the three presets were ready within 3 to 11 s of the first frame on the M5; the 84 s of journal 054 was the vegetation warm-up waiting for one idle period per step (a hidden page gets an idle period every 2 s). | repo's three 0.186.1 `WebGLRenderer.js`, measured (journal 038) |
| Lipschitz cap | If `f` has gradient at most `B` and `g = S (a - f) / B`, then `g` is `S`-Lipschitz, and `min(h, g)` is no steeper than the steeper of `h` and `S`: this keeps the terrain's slope bound while carving a lake's cone (`lakeCap`, `terrain.ts`). Local reasoning, not a published source. | derived, tested in `core/test/lakes.test.ts` |
