# Save and load (plan 043)

Checked **2026-10-17**.

| Topic | Fact used | Source |
|---|---|---|
| IndexedDB quota | Per origin, from the total disk size: Chromium up to 60 %, Firefox min(10 % of disk, 10 GiB) best-effort (up to 50 % when persistent), Safari about 60 % in the browser (about 15 % in embedded WebViews). Writing beyond it fails with `QuotaExceededError`; wrap writes in `try`/`catch` and free space by deleting first. A save is tens to hundreds of KB (the pad vessel is 11 KB, a 100-part vessel with debris a few hundred KB), so quota only matters through eviction and a full disk. | https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria |
| Persistence | Default storage is best-effort and can be evicted under pressure, all-or-nothing per origin. `navigator.storage.persist()` asks for persistent storage: Firefox prompts, Chromium and Safari decide from site engagement without a prompt. Chrome's research says browsers rarely evict regularly visited sites. The save list therefore asks once after the first save and always offers the file export. | same |
| Structured clone | Plain objects, arrays, numbers, strings, `Map`, `Set`, typed arrays and `Blob` clone; functions and DOM nodes throw `DataCloneError`; prototypes are dropped; the page documents no size limit. A `SimSave` is plain JSON-compatible data (tested by `parse(stringify(save)) equals save`), so it crosses `postMessage` and goes into IndexedDB without conversion. | https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Structured_clone_algorithm |
| Rapier determinism | The JS/WASM build is described as cross-platform deterministic for the same Rapier version, the same initial conditions and bodies, colliders and joints created and removed in the same order; initial values must come from deterministic operations. The page says nothing about restoring a simulation, and a rebuilt world has no memory of the contact solver's warm-start impulses. Measured instead (ADR 0050, journal 043): free-flight and rails states resume byte for byte; states touching the ground tile resume to within millimetres. | https://rapier.rs/docs/user_guides/javascript/determinism/ |
| Rapier `takeSnapshot` | The same page uses `world.takeSnapshot()` to hash a world; a byte snapshot of the whole engine exists but is a WASM-internal format tied to the Rapier version. Not used (the project decision is plain data, rebuilt): it would pin saves to a Rapier build and defeat migration. | same |
| JSON number round trip | `JSON.stringify` of a finite double and `JSON.parse` give the same double back (shortest round-trip form, ECMAScript `Number::toString`); `-0` becomes `0` and `NaN`/`Infinity` become `null`, so a save checks every number is finite. | https://tc39.es/ecma262/#sec-numeric-types-number-tostring |
