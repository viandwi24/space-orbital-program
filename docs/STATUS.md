## Phases

- **Phase 0 — Foundation** (plans 001–006): repo, math, core runtime, physics adapter, SDK, stock content. Everything headless; passes in Bun with no browser.
- **Phase 1 — MVP** (plans 007–009): a rocket built from stock parts launches from a spherical home planet, stages, reaches a stable orbit, and the orbit is drawn in a map view. Runs in the browser.
- **Phase 2 — Mod ecosystem** (010+): scripting sandbox, external mod loading, mod patching, save/load.
- **Phase 3 — World**: terrain LOD, more bodies, atmosphere model, re-entry heating.

## Known issues / open questions

- The launch site is body-fixed (0, 0) and the sim places vessels there at any load time (plan 025, ADR 0030). Terrain heights are physical since plan 031 (ADRs 0043, 0044): the sim's ground tile, surface rails and debris rules and the drawn ground read one height function in `core`; trees and buildings beyond the flat zone around the pad stay on the reference sphere, and the terrain is flat within 5 km of the pad. The first body is drawn by the planet pass; other bodies are plain lit spheres. Frame times are measured on an Apple M5 only (plan 039: `high` 6.9 to 14.4 ms and `medium` 7.4 to 12.8 ms sync at pad, 3 km, 12 km, orbit and a hillside; the quality governor is the answer for slower GPUs and has never run on one; a preset switch hitches for 130 to 290 ms); clouds are two flat shells (no volume), the terrain edge is not anti-aliased, and in the hidden browser pane a shader compiled after the first frame ran 3x slower (journal 027, draft plan 031).
- Part visuals (plan 020, ADR 0028; radial hardware by plan 026; effects by plan 033, ADR 0047): debris is cut from the destroyed parts' meshes but vanishes, the re-entry plasma is an ellipsoid shell tinted by speed, smoke is lit, drifting billboards without depth fade, the plume ground light is a faint disc, engines gimbal 3 degrees (no HUD read-out yet; the autopilot and scripts keep wheel-tuned gains); the explosion, vacuum and re-entry screenshots are synthetic snapshots (a real crash is covered by unit tests and the camera hold, not by a capture); the destroyed vessel's camera holds the wreck for 5 s then jumps to the planet centre (HUD "lost" state). Draft plan 033 (also gimbal: a finned rocket resists the reaction wheel at high dynamic pressure, journal 026).
- Vessels on surface rails (ADR 0024) have no colliders: other vessels pass through a parked one. Debris circling inside the atmosphere stays in flight until drag brings it down (ADR 0021). Vite dev reloads the page when a workspace package changes.
- HUD (plan 021, ADR 0026): stage Δv reads module descriptors (`describe`, ADR 0033, plan 024), so a mod's engines and separators count, and the map markers use `Renderer.project`. The HUD throttle gauge still reads the stock engine's snapshot (a mod engine falls back to the page's own value). The layout is tuned for 1280x720 and up, the dev autopilot (`P`) is unreliable under software rendering, and the throttle gauge is read-only.
- VAB (plans 022, 026, 029; ADRs 0029, 0041, 0042): the library is IndexedDB (falls back to memory with a notice), autosave makes a record per started vessel and has no housekeeping; the stability read-out is a small-angle guide that counts `stock.fin` only; group move and turn cover radial symmetry groups; the Δv trip estimate is still a rule of thumb (1.3 km/s allowance, draft 034); frame time measured only on an Apple M5 (VAB `high` 1.0 ms CPU, 179 draw calls at 1440x900 ratio 2; M1/M2 and Intel in draft 033); the hall is much better but the crane is partly out of view from the default camera and the walls are dark; the layout fits 1024x768 and up, narrower windows use drawers.
- Saves (plan 043, ADR 0050): `Sim.save()`/`createSim({ resume })`, the save library and its dialogs are wired into the flight page, pause menu, F5/F9 and the main menu; a resume is byte-exact except while a body touches the ground (bound 5e-3). Scripts are not saved (they stop on load); `save/mods.ts` lists stock plus the booted mods (plan 046); plan 044 must extend `SimSave` for a second body.
- Package scope `@orbital/*` is a placeholder; rename before any publish (ADR needed).
- **License undecided** (README, Credits page, journal 023 release checklist: FAIL). The human decides; an agent must not choose one. Hosting, domain and CDN are also undecided (`architecture/hosting.md`); `VITE_SITE_URL` makes the social image address absolute.
- Release (plan 023): frame times are measured on an Apple M5 only; the live governor run, the first-playable time on a visible M5 pane, the save export download and a screen-reader pass need a person (journal 023, "How to test manually"). Phones and tablets are unsupported; keys are fixed and there is no sound in 1.0 (draft 053).
- `apps/web` uses TypeScript 6.x (pinned by `svelte-check` compatibility) while Bun ships `bun check` against TS 7. Both pass today; revisit when `svelte-check` supports TS 7. Recorded in `research/stack-versions.md`.
- Flight vessels are one rigid compound body (plan 011, ADR 0018): no joint flex; parts only break off by ground impact (plan 012, ADR 0019), not by load or collision between vessels. `createRapierBackend({ solverIterations })` still matters for contacts between bodies. Rapier is f32 and first-order (position error `a·dt·t/8` under constant force).
- Sim limits (see `architecture/simulation.md`): ground tile is a rigid plane fitted to the terrain under the centre of mass (no terrain without a `terrain` option; long vehicles and rovers are not covered; the ocean is solid), lift only from fin-like modules (`stock.fin`, ADR 0035; no control surfaces, no damping term), no tilted parts, simplified re-entry heating (windward area only, no conduction/wake, ADR 0023), one 2.5 km physics bubble, attitude frozen on rails.
- A plugin's `contributes` keys are type-only: declaring one and never calling `ctx.provide` for it is not detected at load time (dependents see `undefined`). See ADR 0013.
- Scripts run in their own Worker per Run (plan 018, ADR 0031): a runaway or wedged script cannot delay a sim tick and is killed after 500 ms without an answer; commands act on data one or more ticks old. The per-tick interrupt budget (10 ms, first tick 200 ms) does not bound native builtins (a long `indexOf` ran 25 s). QuickJS-WASM is unaudited upstream; since plan 030 the script Worker lives in an opaque-origin sandboxed iframe with a no-network CSP (ADR 0038), so an escape reaches no game storage or network, and the panel shows a self-test of that. Plan 032 ran the sandbox in Playwright's Chromium, Firefox and WebKit (all isolated; `product/browser-support.md`); a CSP on the game page is plan 023 (hosting list in `architecture/scripting.md`). The per-tick script budget is 200 ms (10 ms until plan 030).
- Browsers (plan 032, ADR 0040): desktop Chrome/Edge 97+, Firefox 114+, Safari 16+ per the feature tables, tested only in Playwright's Chromium 156, Firefox 157 and WebKit 27.2 (`product/browser-support.md`); phones and tablets are not supported; a browser without WebGL2, Workers or WebAssembly gets a notice. The intermittent "Vessel lost" on the pad was a page-side misreading of a snapshot taken before the load, fixed in plan 047. Time warp works while a script runs by a host-side hold of the script's attitude (ADR 0039); the e2e suite needs `bunx playwright install chromium firefox webkit` once and serves a fresh production build.
