## Phases

- **Phase 0 — Foundation** (plans 001–006): repo, math, core runtime, physics adapter, SDK, stock content. Everything headless; passes in Bun with no browser.
- **Phase 1 — MVP** (plans 007–009): a rocket built from stock parts launches from a spherical home planet, stages, reaches a stable orbit, and the orbit is drawn in a map view. Runs in the browser.
- **Phase 2 — Mod ecosystem** (010+): scripting sandbox, external mod loading, mod patching, save/load.
- **Phase 3 — World**: terrain LOD, more bodies, atmosphere model, re-entry heating.
- **Phases 4–9 — Foundation roadmap F1–F6** (decided 2026-10-17, ADRs 0094 to 0108): worlds and rules, Space Center and sites, career, network and control, time and the real sky, living world. See "Next: foundation roadmap".

- **Unsaved new worlds** (journals 096, 236): in a world with no save yet, Space Center spending and the funds of a branch founding are not carried (the reload starts from the world record).
- **Space Center** (plan 091, journal 091; `core/src/buildings.ts`): an overlap reason names the blocking building by its instance id (`legacy-pad`), not its label; moving a building is remove then place; roads cannot be drawn by hand (not planned). The flight view still draws the hard-coded site layout (`renderer/src/site-buildings.ts`); only the Space Center uses site mode (`setSiteBuildings`), so placed buildings do not appear at launch. Labels of close buildings stack (spread vertically), no clustering.
- **Exact float goldens are platform-specific** (080 merge; 084's terrain and lake digests, fixed to a 1e-9 m tolerance with the SHA-256 kept for arm64): snapshots recorded on Linux x86-64 differ in the last ulp on Apple arm64. - **HUD** (plans 021, 023, 215): the throttle gauge reads the engines' module descriptors (a mod engine counts) and is read-only on the desktop (keys set it; the touch slider is the tablet control, plan 053); the dev autopilot (`P`) is unreliable under software rendering.
- **Hangar** (plans 022, 093, 220; ADRs 0029, 0041): the library is IndexedDB (falls back to memory with a notice), autosave makes a record per started vessel and has no housekeeping; the layout fits 1024x768 and up, narrower windows use drawers.
- **Saves** (plan 043, ADR 0050; plans 077, 230): a resume is byte-exact except while a body touches the ground (bound 5e-3); scripts are not saved (they stop on load, `core/src/save.ts`).
- Package scope `@orbital/*` stays (ADR 0105 point 2: identifiers, file formats and storage keys keep "orbital"); the npm scope for publishing needs its own ADR before any publish. No trademark search has been done for "Space Orbital Program" (the owner should check before a domain or a publish).
- **Hosting** (plan 202, `architecture/hosting.md`): the release workflow publishes to Cloudflare Pages and GitHub Pages builds with a meta CSP; the production host and domain are the owner's choice (plan 232). `VITE_SITE_URL` makes the social image address absolute.
- Foundation risks the owner accepted against the research's advice (recorded in the ADRs with guardrails): a full resource economy from the start (ADR 0098: running costs, damped prices, a career-bot band test, thin slices with the currencies core as fallback), communications tiers 1 to 6 as one programme (ADR 0101), crew as a full simulation (ADR 0100: every aspect a rule, Sandbox off), free grid placement and a 3D Space Center (ADR 0097), both 1:1 and rescaled real systems (ADR 0103: per-scale balance and a validation suite), and announcing the big roadmap (ADR 0108: labels without dates, phase reviews). Pricing and distribution are open (the owner decides).
- Owner confirmed (ADR 0109): control needs a command source like KSP (crew aboard or a linked probe; probes without signal uncontrollable in Career/Science), Career crew preset "standard" plus "hardcore", 10 px text floor.
- **Human passes not done** (journals 023, 055, 058, 072): the live governor run, the first-playable time on a visible pane, the save export download, a screen-reader and keyboard-only pass, a real input method (IME) and dead keys, macOS Ctrl+Space, real tablets and phones (journal 055 checklist, journal 072 "Human checklist").
- **Phones and portrait tablets are unsupported** (ADRs 0063, 0091, 0107 point 6; plan 073 closed without building): tablets in landscape at 1024x768 and up are supported with touch controls (plans 053, 055), tested in emulation only; a smaller screen gets a notice with Continue anyway.
- `apps/web` uses TypeScript 6.x (catalog `^6.0.3`, pinned by `svelte-check` compatibility) while TS 7.0.2 is on npm. Revisit when `svelte-check` supports TS 7 (`research/stack-versions.md`).
- Flight vessels are one rigid compound body (plan 011, ADR 0018): no joint flex; parts break off or are destroyed by impact (per-part `impactTolerance`) or overheating, not by load (struts have no strength, journal 041) or by collision between vessels. `createRapierBackend({ solverIterations })` still matters for contacts between bodies. Rapier is f32 and first-order (position error `a·dt·t/8` under constant force).
- Sim limits (`architecture/simulation.md`): the ground tile is a rigid plane fitted to the terrain under the centre of mass (long vehicles and rovers are not covered); lift from fins, wings and control surfaces (ADRs 0035, 0045, 0075); simplified re-entry heating (ADR 0023; journal 212: the renderer's plume and re-entry effects and the aero readout still use their own isothermal density); one 2.5 km physics bubble; attitude frozen on rails.
- A plugin's `contributes` keys are type-only: declaring one and never calling `ctx.provide` for it is not detected at load time (dependents see `undefined`). See ADR 0013.
- Scripts run in their own Worker per Run (plan 018, ADR 0031) inside an opaque-origin sandboxed iframe with a no-network CSP (plan 030, ADR 0038): a runaway script is killed after 500 ms without an answer; commands act on data one or more ticks old. The per-tick budget (200 ms) does not bound native builtins (a long `indexOf` ran 25 s). QuickJS-WASM is unaudited upstream.
- Browsers (plan 032, ADR 0040; `product/browser-support.md`): desktop Chrome/Edge 97+, Firefox 114+, Safari 16+ per the feature tables, tested only in Playwright's Chromium 156, Firefox 157 and WebKit 27.2 (a Safari preview, not Safari); a browser without WebGL2, Workers or WebAssembly gets a notice. The e2e suite needs `bunx playwright install chromium firefox webkit` once and serves a fresh production build.
