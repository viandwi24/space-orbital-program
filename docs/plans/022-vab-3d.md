# 022 — UI: 3D vehicle assembly building

## Goal

The VAB becomes a 3D editor: a procedural hangar, the vessel rendered with the 020 part models, a part catalogue with rendered icons and categories, attaching parts by picking highlighted nodes in 3D, a stage editor, live Δv/TWR per stage (sea level and vacuum), validation warnings, undo/redo, and save/load — styled with the 021 design system.

## Context

- Read: `docs/product/visual-direction.md`, ADR 0016 (design format), `apps/web/src/routes/vab/*`, `apps/web/src/lib/design.ts`, journals 009, 020, 021.

## Scope

**In:** hangar scene, orbit camera, part icons rendered off-screen from the generators, catalogue search and categories, node picking (raycast) and ghost preview, detach/delete, symmetry not required, stage editor (drag between stages), Δv/TWR readouts (shared pure function with the HUD), warnings (no control source, no stages, TWR < 1 at liftoff, unattached nodes), undo/redo, name the vessel, save/load JSON, launch button.
**Out:** radial attachment and symmetry (needs sim support — draft a plan if wanted), assets.

## Steps

1. Refine; ADR 0029 (editor state model, loose assemblies, staging, view split). Research in `docs/research/vab-editor.md`.
2. Editor core in `apps/web/src/lib/editor/` (state, attach targets, staging, checks, categories, trip estimate) with vitest tests.
3. Renderer `packages/renderer/src/vab/` (hangar, orbit camera, picking, node markers, highlights, icons) with Bun tests for the pure parts.
4. VAB route: catalogue, stage editor, stats strip, warnings, launch, keyboard operation, save/load.
5. Manual run in the built-in browser, screenshots, frame time, journal with self-review.

## Acceptance criteria

- [x] `bun --cwd apps/web run test` (vitest): editor tests pass. They cover attach / detach / move subtree / delete, undo / redo (including redo cleared by a new edit), stage editing (move a part between stages, insert a stage, auto-staging of a new engine and of a new decoupler reproduces the stock `referenceTwoStage` stages, manual edit turns auto-staging off), `attachTargets` (stack rule, empty design offers root), and `checkDesign` (no control source, no stages, TWR < 1 at liftoff, empty stage, unstaged engine, loose parts, empty design is an error).
- [x] Readout test: the stats model for `referenceTwoStage` equals `stageDeltaV(stagingModelFromDesign(...))` at sea level and in vacuum (same numbers as the plan 021 test, per stage and total), and the liftoff TWR equals `twr(stage 0 sea-level thrust, mass, g)`.
- [x] `bun test` in `packages/renderer`: orbit-camera maths (pitch clamp, zoom limits, pan), node picking (`pickNode` nearest hit, miss), framing, and placement-diff tests pass; `tokens.test.ts` still passes (any new text token is contrast-tested).
- [x] `[manual]` In the built-in browser at `/vab` build the two-stage vessel entirely in the 3D view with the mouse (pod, wheel, tank, engine, decoupler, tank, engine by picking catalogue parts and clicking highlighted nodes), and once more with the keyboard only (catalogue Enter, Tab through nodes, Enter to place); the stage stack shows Δv within 1 m/s of the plan 021 test values for the same design; Launch; `/flight` reaches orbit (sample script or dev autopilot allowed); save JSON, clear, load JSON gives the same design.
- [x] `[manual]` Screenshots `docs/journal/assets/022-*.png` at 1920x1080 and 1280x720: empty hangar with the catalogue, mid-build with node highlights and ghost, finished vessel with the stage stack and Δv, warnings state.
- [x] `[manual]` Frame time of the VAB scene with the finished vessel recorded in the journal (1080p, M-class laptop).
- [x] Keyboard operation (every control reachable, visible focus) and AA contrast per ADR 0026; written self-review against `docs/product/visual-direction.md` in the journal.
- [x] `bun test`, `bun run typecheck`, `bun run build`, `bun run docs:check`, `bun run lint`/prettier clean.
