# 022 — UI: 3D vehicle assembly building

## Goal

The VAB becomes a 3D editor: a procedural hangar, the vessel rendered with the 020 part models, a part catalogue with rendered icons and categories, attaching parts by picking highlighted nodes in 3D, a stage editor, live Δv/TWR per stage (sea level and vacuum), validation warnings, undo/redo, and save/load — styled with the 021 design system.

## Context

- Read: `docs/product/visual-direction.md`, ADR 0016 (design format), `apps/web/src/routes/vab/*`, `apps/web/src/lib/design.ts`, journals 009, 020, 021.

## Scope

**In:** hangar scene, orbit camera, part icons rendered off-screen from the generators, catalogue search and categories, node picking (raycast) and ghost preview, detach/delete, symmetry not required, stage editor (drag between stages), Δv/TWR readouts (shared pure function with the HUD), warnings (no control source, no stages, TWR < 1 at liftoff, unattached nodes), undo/redo, name the vessel, save/load JSON, launch button.
**Out:** radial attachment and symmetry (needs sim support — draft a plan if wanted), assets.

## Steps

1. Refine; ADR if the editor state model needs one.
2. Implement; vitest tests for editor state (attach/detach/undo/redo, stage editing, validation).
3. Screenshots; journal.

## Acceptance criteria

- [ ] To be made measurable at refinement. Must include: vitest tests for the editor state machine and validation; `[manual]` build the two-stage vessel entirely in 3D, see Δv ≈ the stock journal values, launch it, reach orbit (autopilot or script allowed for flying); screenshots `docs/journal/assets/022-*.png`; self-review; all repo checks pass.
